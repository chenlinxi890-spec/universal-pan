# 通用网盘（网页版）

粘贴任意网盘的分享链接，就能下载并解压里面的文件。免费，不用登录自己的网盘账号。

## 访问地址

本地运行后打开 http://localhost:8000 使用。

如需从外网访问，把 8000 端口经 Cloudflare Tunnel、Tailscale Funnel 或其他隧道服务暴露出去即可（仓库附带一个 Cloudflare quick tunnel 的 systemd 服务示例 `unipan-tunnel.service`，仅作参考）。

## 上传文件

浏览器里把本地文件传到通用网盘自己的服务器（不是传进百度/夸克网盘，那要登录账号，本工具不碰账号）：

- 传上去的文件存在服务器 `/data/uploads` 下；压缩包（zip/7z/rar）传完自动解压，和下载的流程一样。
- 大文件分片上传、断点续传：文件切成 4MB 一片依次传，单片失败自动重试；刷新页面后重选同一文件可续传未传完的分片。
- 每个上传生成一个公开分享链接（`/share/<id>`），点开就能下载原文件、解压出的单个文件，或整包打包下载。
- 需要发给买家时，可以在文件库里为该文件生成一次性链接（见下节），下载一次后失效。

## 一次性下载链接

永久分享链接不适合当发货链接（拿到链接的人能一直下载，还能转给别人）。一次性链接按订单现生成，一个买家一个链接：

- 文件库里每个上传都可以生成多个一次性链接（`/once/<id>`），每个链接有自己的状态（未使用/已使用）、生成时间、使用时间。
- 一次性链接的分享页只提供一个下载动作：下载原文件，不提供单个解压文件下载、不提供重新打包下载。页面上标明“一次性链接，下载一次后失效”。
- 语义：只有一次下载完整传完才算用掉（服务端确认整个文件流发完后才标记已使用）；下载中途断开（客户端断开、没传完），链接不算用掉，还能再下。第二次打开或下载已用过的链接，明确显示“链接已使用过，已失效”。
- 文件库里列出每个上传已生成的一次性链接（状态、生成时间），能复制链接，能作废（删除）未使用的一次性链接。删除上传时，其下的一次性链接一并删除。
- 状态存在 `store.json` 里，重启服务后仍在（已使用的不会复活）。
- 只支持上传文件的一次性链接；从网盘下载的分享暂不支持。
- 注意：一次性链接按订单现生成，不能写进固定发货模板里重复使用（第一单用完即失效），适合手动发货时现生成现发。
- “文件库”列出所有已上传和已下载的文件/任务，支持删除、单个下载、整包打包下载；“任务历史”保留解析/下载/上传的任务记录和状态，刷新页面后还在。

## 实测结果（2026-11-11，本地实测）

- **夸克 ✅ 全流程跑通**：真实夸克分享链接解析出
  `V8-HEART-OF-MOTION-制作提示词.docx`（60201 字节），下载完成，文件落盘，
  经校验是真实 docx（PK\x03\x04 开头，SHA256 `207db46d…351f`）。
- **百度：解析 ✅，下载 ❌（百度服务端限制）**：真实百度分享链接解析出
  `AI视频提示词合集-222条-中英对照.zip`（54268 字节）；但 `sharedownload`
  返回的直链签发即过期（`dstime`=签名时间-3600，`expires=1h`），下载一律
  403 `{"error_code":31360,"error_msg":"expire time out error"}`，与
  UA/Cookie/Referer/clienttype/app_id 无关，各百度服务器时钟与本地时钟相差 <1s、
  非时钟问题；`sign` 绑定 tplconfig 时间戳，改时间戳报 113；`filemetas`
  需登录（errno -6）。结论：百度游客只能解析列表，下载需登录百度账号
  （本工具不碰账号）或转存后下载。页面上会如实显示这条原因。
- **解压 ✅**：解压器（7z）已验真，zip 解压出文件并在页面列出。
- **其余 8 家**：无真实分享链接可测，用示例格式链接自测，解析逻辑均通，
  均返回各家真实的“分享不存在/失效”类错误（见上表），未编造成功结果；
  下载环节除迅雷/139/123（明确需登录）外均未实测。
- **迅雷**：游客列表接口现返回 `captcha_invalid`（缺 captcha_token），
  游客解析暂不可用，页面如实报错，建议用迅雷客户端打开。
- **上传 ✅（2026-11-11 新增，本地实测）**：54KB 压缩包和 33.8MB 压缩包分片上传均成功，传完自动解压（分别解出 5 个和 94 个文件），分享链接打开能下载原文件（SHA256 与原文件一致），整包打包下载正常；刷新后续传、重启后文件库和分享链接仍在。
- **阿里/天翼 ✅（2026-11-11 新增）**：链接识别和解析链路用假分享码调真实服务器验证，均返回各家真实的“分享不存在”类错误；阿里游客下载接口已实现（待真实分享验证），天翼下载需登录账号、已明确报错。
- **一次性链接 ✅（2026-11-11 新增，本地实测）**：英语合并包生成一次性链接，完整下载一次 SHA256 与原文件一致，第二次下载 410、分享页显示“链接已使用过，已失效”；中途断开（只下前 4KB 即断）后链接仍未使用，之后完整下载成功；新链接可用；作废后 404；容器重启后已用链接仍 410、未用链接仍可下载；永久分享链接不受影响。实现细节：uvicorn 的 send() 在客户端断开后静默返回不抛异常，下载端另起任务监听 http.disconnect 来发现中途断开；一次性下载用 @app.api_route(methods=["GET", "HEAD"])，HEAD 只取响应头、不消耗链接；并行双下同一链接时一个 200、另一个 409。
- **已知问题**：部分代理环境下可能出现 POST 请求卡住，改用直连地址即可。

## 本地运行

```bash
python3 -m venv venv && venv/bin/pip install -r requirements.txt
venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

打开 http://localhost:8000 使用。

## Docker 部署

```bash
docker build -t universal-pan .
docker run -d --name universal-pan -p 8000:8000 -v universal-pan-data:/data universal-pan
```

## 红线

只下载用户自己提供链接和提取码的分享文件；不登录、不转存、不破解会员、不绕限速。
解析失败、链接失效、需要登录才能下的情况如实报错，不编造。
